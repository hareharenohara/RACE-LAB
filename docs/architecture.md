# JRA専用MVP設計

## 実行フロー

1. Supabase Cronが毎日07:00 JSTに`jra-weekend-daily`を呼び出す。
2. JRA開催がない日は一覧取得1回だけで正常終了し、Geminiを呼び出さない。
3. 同日成功済みのバッチがあれば終了し、重複実行を防ぐ。
4. JRAの当日レース一覧を取得して正規化・保存する。
5. Geminiへ選定用JSONを1回送信し、戦略ごとに最大3レースを選ぶ。
6. 選定レースの出馬表とオッズを取得する。
7. 保守型・バランス型・積極型ごとに1回ずつGeminiへ予想を依頼する。
8. JSON Schema、券種、馬番、100円単位、実在オッズを検証して保存する。
9. 入出力ハッシュを保存し、予想台帳を固定する。

Geminiの利用は通常1日4リクエストです。

## セキュリティ

- フロントエンドにはSupabaseの公開可能なキーだけを置く。
- Gemini APIキーとSupabase secret keyはEdge Function secretsに保存する。
- Cron呼び出しはVault内の`batch_secret`で認証する。
- 公開スキーマの全テーブルでRLSを有効化する。
- 認証済み所有者だけに読み取りを許可し、ブラウザへ書き込み権限を与えない。

## 予想ルール

- 期待値は`estimated_probability × odds_at_prediction`で記録する。
- 固定の購入上限は設けず、買い目は100円単位とする。
- BOX・フォーメーションは個別の買い目に展開して保存する。
- 期待値や根拠が弱い場合は`SKIP`を許可する。
